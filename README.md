# Интеграция формы заявок с Bitrix24 #
## Требования

- PHP с расширением `curl`.
- Composer.
- Доступный входящий webhook Bitrix24.

Установка зависимостей:

```bash
composer install
```

## Настройка webhook Bitrix24

1. В Bitrix24 откройте раздел для разработчиков и создайте входящий webhook.
2. Дайте webhook права на CRM и задачи, так как проект создает лиды и задачи.
3. Скопируйте URL webhook. Обычно он выглядит так:

```text
https://example.bitrix24.ru/rest/<USER_ID>/<TOKEN>
```

4. Создайте файл `.env` на основе `.env.example`.
5. Заполните переменные:

```dotenv
BITRIX24_WEBHOOK=https://example.bitrix24.ru/rest/<USER_ID>/<TOKEN>
BITRIX24_RESPONSIBLE_ID=1
BITRIX24_DOMAIN=example.bitrix24.ru
```

`BITRIX24_WEBHOOK` можно указывать с любым REST-методом в конце. В коде из него берется базовый путь `/rest/<USER_ID>/<TOKEN>/`, а нужный метод подставляется динамически.

## Где хранится webhook URL

Webhook URL хранится в файле `.env` в переменной:

```dotenv
BITRIX24_WEBHOOK
```

Чтение выполняется в `function.php` через функцию `getBitrix24WebhookUrl()`. В репозиторий нужно добавлять только `.env.example`; реальный `.env` содержит секретный токен и не должен попадать в Git.

Для построения ссылок на лиды в отчете домен берется из `BITRIX24_DOMAIN`. Если переменная не задана, `report.php` достает домен из `BITRIX24_WEBHOOK`.

## Использованные методы Bitrix24

Проект обращается к Bitrix24 REST API через входящий webhook.

- `crm.lead.add` - создание лида из данных формы.
- `crm.lead.fields` - получение списка полей лида, используется на странице `field.php`.
- `crm.status.list` - получение источников лидов (`ENTITY_ID = SOURCE`) для поля "Источник" в форме.
- `task.item.add` - создание задачи ответственному сотруднику после успешного создания лида.

Общий вызов API реализован в `callBitrix24Api()`. Метод передается строкой, например `crm.lead.add`, а URL собирается функцией `getBitrix24RestUrl()`.

## Использованный публичный API

Для получения курсов валют используется публичный API с ежедневными курсами ЦБ РФ:

```text
https://www.cbr-xml-daily.ru/daily_json.js
```

Курсы запрашиваются в `getCurrencyRates()` и используются в `report.php` для пересчета суммы заявки из рублей в USD и EUR.

Данные кэшируются в файле:

```text
data/rates.json
```

Если кэш младше 24 часов, новый запрос к публичному API не выполняется.

## Обработка ошибок API

### Bitrix24

При вызове Bitrix24 проверяются:

- ошибка cURL;
- HTTP-код, отличный от `200`;
- поле `error` в JSON-ответе Bitrix24.

Результат возвращается из `callBitrix24Api()` в виде массива:

```php
[
    'success' => true или false,
    'data' => декодированный JSON-ответ,
    'error' => текст ошибки или null,
]
```

Все запросы к Bitrix24 логируются в:

```text
data/log_bitrix.log
```

При логировании токен webhook маскируется, а персональные данные заявки скрываются.

### Публичный API курсов валют

При запросе курсов проверяются:

- ошибка cURL;
- HTTP-код ответа;
- наличие нужных значений `USD` и `EUR` в JSON.

Запросы логируются в:

```text
data/log_public_api.log
```

Если свежие курсы получить не удалось, код пытается вернуть последний сохраненный кэш из `data/rates.json`. Если кэша нет, функция возвращает `null`, а отчет показывает сообщение о недоступности курсов.

### Локальная обработка формы

Перед отправкой в Bitrix24 форма проверяет обязательные поля, корректность email и положительную сумму. Результат каждой попытки сохраняется в:

```text
data/bitrix_leads.json
```

В файл записываются локальный ID, ID лида Bitrix24, статус, ошибка и исходные данные заявки.

## Что улучшить в production-версии

- Включить проверку SSL-сертификатов (`CURLOPT_SSL_VERIFYPEER => true`) и корректно настроить CA-сертификаты на сервере.
- Добавить таймауты и retry-механику для Bitrix24 API, особенно на временные сетевые ошибки и лимиты.
- Хранить заявки не в JSON-файле, а в базе данных с транзакциями, индексами и нормальной историей статусов.
- Добавить авторизацию для страниц отчета и списка полей, чтобы данные заявок не были публичными.
- Валидировать и нормализовать телефон, источник заявки и сумму на сервере более строго.
- Добавить CSRF-защиту для формы.
- Использовать централизованный логгер с ротацией логов и уровнями `info`, `warning`, `error`.
- Не сохранять лишние персональные данные в логах и продумать срок хранения заявок.
- Добавить мониторинг ошибок интеграции и уведомления при сбоях Bitrix24 или публичного API.
- Покрыть критичные функции автотестами: сборку REST URL, обработку ошибок API, кэширование курсов и валидацию формы.
